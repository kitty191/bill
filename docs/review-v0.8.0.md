# v0.8.0 审查

日期：2026-11-06 至 2026-11-07（Asia/Shanghai）。范围为 Android 后台文件备份、原签名一键发布及回归发现的网页快速切页问题。账本 schema 仍为 4，原签名保留。

- 后台备份需单独开启，旧配置默认关闭；复用完整 JSON 验证、七份有效版本与可见错误。首次后台执行生成首份副本，之后按到期频率执行；最近后台成功时间独立记录。关闭频率同时关闭后台开关，残留已排队任务也会检查配置。
- 前台 / 手动 / 后台统一读取磁盘中的最新已提交账本，租约放在独立 SQLite 数据库，写入、读取、清理与更新配置前验证所有权。过期拥有者无法删除新任务租约或覆盖新设置；未完成文件不能挤掉有效版本。
- 系统任务在模块初始化阶段定义，支持缓存进程回收后的无界面加载。默认每小时由系统检查是否到期；Android 省电 / 网络状态可能延迟执行，系统强行停止后需重开。后台读取不经过界面应用锁，导出文件不加密；iOS / 网页保持前台备份。
- 发布脚本真实执行检查、原签名构建和校验、提交推送、创建预览 Release 和匿名下载核验。强制验证版本递增、原证书、Release / ARM64、字节数、SHA-256、CRC、16 KB 对齐、内置模块与计数器缺席；没有匹配 Android 应用 / 构建输入的原生成功验收就停止。它不向 GitHub 上传私钥，尚未启用常驻无人值守签名服务。
- 完整浏览器检查发现一次快速触摸甩动越过两页。网页改为单一吸附目标，并将触摸惯性限制在起始页相邻一页；dock 点击 / 尺寸变化可立即解除约束。修复后的同一图表取消与快速切页用例连续 10 次通过，没有放宽断言；手机端仍使用独立原生分页。

- 原生首次启动检查复现了压缩版 WorkManager 初始化崩溃：Room 的生成数据库无参构造函数被 R8 移除。无界面任务使用反射加载的 `ExpoModulesPackageList.getPackageList()` 也需要保留名称。新增两条精确保留规则，并在最终 APK 的 R8 映射中验证构造函数和反射入口；没有关闭整个压缩优化。
- 原生验收脚本曾点击“允许系统后台备份”的静态文字，未触发同名 Switch。根据失败时实际 UI 层级修正为优先查找可交互节点，并要求开关的 checked 状态确实改变；财务数据、文件内容及后台成功断言保持严格。
- 开关修正后，实际设备日志与界面确认任务注册成功。API 35 的 WorkManager 使用带命名空间的 JobScheduler 条目，验收脚本旧格式匹配漏掉了 job 0；现同时识别新旧格式，按命名空间触发对应应用的任务，附实际格式回归测试。
- 一轮目录重启验收在文件刚可读取时强行结束进程；日志显示文件读取与 force-stop 同在 `12:01:53`，尚未保存成功状态 / 释放互斥租约。重启检查现等待该文件名出现在成功状态且备份操作结束；后台文件在无界面状态生成并核对后，重新打开界面不再先 force-stop，并额外确认旧进程确实消失、新任务启动了不同进程。没有放宽文件内容或财务断言。真正的备份中断可能保留租约最多 30 分钟，超时回收与旧写入者保护由独立 SQLite 测试覆盖，未宣称立即恢复。
