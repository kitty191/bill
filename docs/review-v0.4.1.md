# v0.4.1 发布前审查

日期：2026-11-04。

本轮按用户选择，只做大账本性能优化。主导航与现有功能入口保持简洁。

## 列表与搜索

- 账单页使用独立 SectionList，替代一次挂载所有记录的 ScrollView。日期分组卡片、列表头、完整结果汇总及空状态保留；虚拟化只减少视图数量。
- 显式计算分组与行布局，首次可见记录提供实际尺寸，屏宽 / 字体缩放变化时重新测量。测试可直接翻到一万条记录的末尾，窄屏后仍可编辑最早记录。
- 按账单、分类、账户引用缓存排序和大小写归一的检索文本；输入与结果计算分离。账户重命名、隐藏分类、转入账户、清除关键词和排序并列顺序均有覆盖。
- 普通切页保留位置与条件；首页「查看全部」和「今日支出」沿用原有重置行为。窄屏金额摘要与单行记录适配字号，完整金额继续保留于可访问文本。

## 手机保存

- 当前账本仍保存完整 JSON，财务校验继续执行。最近 5 份快照改为分别存行，只插入新增版本，避免每次拼接 / 重写整个历史数组。
- 旧历史在首次需要保存快照时迁移，保留原版本 ID、内容、时间和顺序；相同时间戳仍按原顺序排列。迁移、裁剪和当前账本写入在同一 SQLite 事务内。
- 覆盖新旧快照与主账本失败回滚、迁移重试、损坏历史清理，以及升级原始备份保留。损坏旧历史不会阻止读取有效的当前账本；恢复仍验证所选快照。
- schema 仍为 4，导出 JSON 和网页历史格式不变。网页继续使用 localStorage，全量保存和容量限制仍存在。

## 测量

同一云端 Chromium、390 × 844 视口、10,000 条生成记录，优化前后各一次样本：

| 项目 | v0.4.0 | v0.4.1 |
| --- | ---: | ---: |
| 账单首屏挂载行 | 10,000 | 11 |
| 启动至首页金额可见 | 16,782 ms | 1,185 ms |
| 进入账单页 | 8,689 ms | 171 ms |
| 搜索唯一记录 | 2,145 ms | 134 ms |
| 清除搜索 | 11,344 ms | 131 ms |
| 网页记账保存 | 502 ms | 571 ms |
| 测量结束 JS 堆 | 806.7 MB | 49.2 MB |

网页保存未显示改善；本轮保存优化位于手机 SQLite 适配器。使用相同 10,000 条记录、5 份历史的 Node SQLite 内存数据库运行实际存储 SQL：一次常规保存的写入参数从 **11,518,362 字节降至 3,338,813 字节，减少约 71%**。保存并读取历史的单次测量从 480 ms 至 158 ms；该时间包含读取、解析与验证历史，不是纯写入耗时，也不代表 Expo 原生桥或手机磁盘性能。首次旧历史迁移仍需读取并写入原有版本。

原始结果见 [大账本测量](large-ledger-performance-v0.4.1.json)。这些是云端单样本比较，受环境影响，不构成真机帧率或延迟保证。

## 验证与限制

- 类型检查、186 项单元 / 组件测试、网页生产导出、完整 47 项交互回归通过。窄屏摘要字号调整后，一万条记录用例再次通过。
- 交互核对完整合计、搜索 / 清除、无结果、列表末尾跳转、切页保留位置、320 px 深色布局、编辑老记录并保留全部 ID，以及首页入口回到顶部。
- 1000 条记录、9 次切页，首页 / 账单 / 统计均 0 次重复渲染，无运行异常，见 [切页测量](paging-performance-v0.4.1.json)。
- 实际生成账本截图见 `previews/large-ledger-v0.4.1-dark.png` 和 `previews/large-ledger-end-v0.4.1-dark.png`。
- APK 构建、签名和导出结果见 [验证记录](validation.md)。云端没有进行真机安装、原生 SQLite 桥、动态字体、快速触摸和后台验收；iOS 代码导出不等于可安装 IPA。
