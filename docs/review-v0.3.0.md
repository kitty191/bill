# v0.3.0 发布前审查

日期：2026-11-04。

审查覆盖金额计算、日期选择、组合筛选、按月预算、撤销删除、升级快照和面板交互。

## 已修正的边界

- 计算器展开且未确认结果时，禁止保存旧金额。输入只允许数字和运算符，不使用动态执行；有理数计算仅在最后四舍五入到分，拒绝除零、非正值和越界结果。
- 日历与计算器互斥，两个筛选日历互斥。展开内容会滚入视野，收起计算器后回到金额；修正窄屏键盘按键换行和日期标签被压缩的问题。
- 筛选日期包含起止两天；开始日期晚于结束日期不得应用。转账可以匹配转入账户，历史隐藏分类仍能检索；筛选汇总按结果计算，退款沿用原支出期间口径，并另列实际到账额。
- 长日期范围按日一次分组，复用全部退款信息，避免每个日期重复扫描账本。数据替换后，失效的账户 / 分类筛选自动重置。
- schema 1 / 2 升级为 3 时保留旧共享预算作为默认值，月份覆盖项独立保存，显式 0 关闭该月。首次写入前保存原始快照，快照失败不得覆盖主账本。
- 导出升级前快照优先使用本次升级前的完整账本，而非更早的 v1 快照；旧快照仍保留。SQLite 的快照与主记录写入同一事务，网页先存快照再替换主键。
- 撤销只针对最近一笔单笔删除，8 秒内有效。在写入队列实际开始时重新检查期限和引用；不覆盖同 ID 记录，不绕过退款上限。恢复失败不改已提交账本，清空 / 示例 / 备份恢复会清除撤销。
- 财务变更和显示偏好继续共用串行写入队列；财务数据在持久化成功后提交，账户显示开关即时反馈、失败回退。

## 验证与限制

逻辑测试覆盖金额边界、闰年日期、预算迁移 / 隔离、组合筛选、日分组、撤销成功 / 失败 / 过期 / 排队过期和关联退款保护。浏览器回归包含实际点击、备份文件读取、快照保存失败、窄屏深色和原有手势流程。

实际网页截图见 `docs/previews/*v0.3.0*.png`。完整测试、打包和安装包校验结果见 [验证记录](validation.md)。

云端未进行真机安装、触摸帧率、系统键盘和 SQLite 原生运行验收。指纹 / Face ID 为系统接口模拟测试，iOS 代码导出不能代替可安装 IPA；正式 iOS 分发仍需 Apple 构建与签名条件。
