# 产品与设计决策

## 目标

做一款同时支持 iOS / Android 的个人记账 App。极简、清爽，具有 iOS 风格的玻璃材质、丝滑且自然连贯的过渡。使用者负责后期审查，日常实现选择由 Codex 自主推进。

暂定名「清账」，默认中文、人民币、本地优先。主导航只放首页、账单、统计；记一笔为独立常驻入口。账户、预算、备份放在设置中。

## 视觉

- 暖白画布、森林绿文字、薄荷绿强调。浅色与深色分别定义色板。
- 收支数字是视觉中心。正文稳定，玻璃仅用于浮动导航，避免多层透明面板造成噪声。
- 系统字体、充足留白、轻边界。类别颜色仅辅助识别。
- Android 12+ 使用 `BlurTargetView` 与原生模糊，旧版采用半透明降级。

## 动效

- 导航指示器采用可中断的弹簧位移，而不是瞬间切换背景。
- 记账按钮按压后轻微缩放、回弹；手机上尝试轻触反馈，能力缺失不阻塞操作。
- 页面与面板短距离淡入；面板拖动跟手，下拉可关闭，未达阈值时回弹。
- 跟随系统减少动态效果设置。后续以两端真机的帧率、手势和键盘表现校准。

## 当前范围

先把手动记账、账户、转账、统计、预算、备份恢复做成完整闭环。首次空账本，不把示例数据混入真实记录。金额用整数分，导入严格验证，持久化成功后才更新界面。

暂缓登录、云同步、家庭账本、OCR、自动导入、复杂预算和多币种，待核心体验通过审查后按需求扩展。

## 后续阶段

1. 产品审查：名称、视觉密度、记账面板的快捷程度、分类与账户默认值。
2. 原生实机：iOS / Android 安装与回归、SQLite、分享 / 文件恢复、中文键盘、手势、减少动态效果、VoiceOver / TalkBack、动态字体、低端设备性能。
3. 发布准备：正式包标识与图标、隐私说明、签名与商店材料、测试分发、数据库迁移策略。
4. 进阶需求：在明确数据恢复和隐私模型后决定云备份与同步。
