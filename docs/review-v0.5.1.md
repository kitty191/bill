# v0.5.1 整体审查与修复

日期：2026-11-05。

本轮审查记账与计算、转账 / 退款、统计与筛选、本机快照、备份恢复、隐私和手势交互。修复四处可复现的问题，保留 v0.5.0 的视觉与功能范围。

## 发现与修复

| 问题 | 触发与修复 |
| --- | --- |
| 自己导出的较大 JSON 不能回导 | 50,000 条记录、每条 120 字中文备注的合法账本导出成功，原导入端却在 10 MB 拒绝。现统一导入与 JSON 导出的 64 MB 上限，检查 UTF-8 实际字节数；缺失文件大小时也验证正文。超限文件在导出前报错，避免生成超出恢复能力的 JSON。 |
| 带 UTF-8 标记的 JSON 导入失败 | 原生文件读取或编辑器保留文件开头的 BOM 时，直接 JSON.parse 会失败。现在去掉开头标记后继续严格验证版本、金额、日期和引用；未知版本与无效数据仍拒绝。 |
| 窄屏大金额与小数被省略 | React Native Web 不实现 adjustsFontSizeToFit。现在测量实际文本，按可用宽度缩小字号，保留金额原值；以原始字形宽度计算，避免反复缩小，并忽略旧布局回调。覆盖主金额、今日支出、负结余及小数边界，调整原生最小缩放比例以容纳较长汇总。 |
| 旧支出改为转账时默认转入 / 转出相同 | 原转入账户按记账默认账户推断，而非当前账单账户。现在基于实际转出账户选择不同的转入账户，切换为转账时重新校验，保留已经有效的用户选择。修改保留原 ID、金额和创建时间，转账继续不计收入与支出。 |

备份上限不等于浏览器存储容量；网页仍受 localStorage 容量限制。schema 保持 4，不改变已保存账本、预算、周期规则、快照与设备隐私设置。
